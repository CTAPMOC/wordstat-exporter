# Wordstat Exporter

Локальное приложение для сбора семантики Яндекс Wordstat в единый Excel. Вход, запуск сбора, история и скачивание защищены общим паролем.

## Запуск

Требуется Node.js 22 или новее. Установка зависимостей и сборка интерфейса из корня проекта:

```powershell
npm install --prefix server
npm install --prefix client
npm run build --prefix client
```

Создайте `server/.env` по примеру `server/.env.example`. Укажите существующие `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Не перезаписывайте рабочий `.env` примером, если ключи уже настроены.

Создать или сменить пароль:

```powershell
cd server
npm run password
```

Команда генерирует случайный пароль, показывает его один раз в терминале и сохраняет только scrypt-хеш с индивидуальной солью в `server/.env`. Другие настройки сохраняются. Передайте пароль доверенным людям. После смены пароля перезапустите сервер: существующие сеансы завершатся. Сам `.env` не зашифрован; API-ключ в нём необходимо защищать правами доступа к компьютеру. Пароль не хранится ни в открытом виде, ни в исходниках интерфейса.

Запуск готового приложения из папки `server`:

```powershell
npm start
```

Откройте http://127.0.0.1:8788. Для разработки запустите `npm run dev` отдельно в `server` и `client`; интерфейс доступен на http://127.0.0.1:5173, запросы к API проксируются на сервер. При изменении серверного порта обновите прокси в `client/vite.config.js`.

## Сбор семантики

1. Войдите по общему паролю.
2. Вставьте исходные фразы, по одной на строку. Пустые строки и точные дубли удаляются. Максимум 2 000 исходных фраз за запуск, до 400 символов каждая.
3. Выберите регион. По умолчанию — все регионы, как на скриншоте Wordstat. Доступны также Россия, Москва и Санкт-Петербург.
4. Нажмите «Начать сбор». Запросы выполняются последовательно на сервере; между ними пауза 500 мс. Временные ошибки повторяются до четырёх попыток.
5. Скачайте общий XLSX после завершения. Счётчики отдельно показывают исходные запросы, строки семантики и уникальные фразы.

Приложение получает данные через официальный API, а не нажимает кнопку скачивания на сайте. Для каждого запроса отправляется `numPhrases: 2000` — максимум API; все элементы `results` и `associations` сохраняются. Данные относятся к последним 30 дням и всем устройствам. Если группа достигла лимита, интерфейс и Excel показывают предупреждение. Это вся семантика полученного ответа, а не обещание неограниченной выгрузки: у этого метода нет параметра следующей страницы. Рекурсивное расширение по найденным фразам не выполняется.

Документация Яндекса: https://aistudio.yandex.ru/ru/docs/search-api/api-ref/Wordstat/getTop

Сбор через API тарифицируется Яндексом. Число повторных попыток может увеличивать количество обращений; фиксированная стоимость в интерфейсе не обещается.

## Что в Excel

- **Исходные запросы**: каждая исходная фраза, общая частотность `totalCount`, статус, число популярных и похожих фраз, регион, время, достижение лимита и ошибка при наличии.
- **Семантика**: все популярные и похожие фразы с частотностью, исходным запросом и названием группы. Повторы между источниками и группами остаются, частотности не суммируются.
- **О выгрузке**: параметры запуска и ограничения источника.

Общая частотность исходного запроса и частотность строки популярной фразы сохраняются раздельно — они могут отличаться. Если популярных фраз нет, сохраняются исходная фраза и `totalCount`, даже при отсутствии похожих фраз. Нулевой ответ получает статус «Нет данных». При технической ошибке исходная фраза остаётся в файле с пустой частотностью и статусом «Ошибка».

При заполнении листа Excel создаётся следующий лист «Семантика 2» и т. д. Выгрузка использует потоковую запись, чтобы не держать весь большой Excel в памяти. Значения частотностей длиннее 15 цифр записываются текстом, чтобы Excel не округлял их.

## Сохранение и восстановление

Каждый запуск хранится отдельно в `server/exports/<ID>/`:

- `batch.json` — исходный список, параметры и прогресс;
- `0.json`, `1.json`, … — полные ответы Wordstat и сведения об ошибках по каждой фразе;
- `wordstat-<ID>.xlsx` — итоговый Excel.

Ответ сохраняется на диск до обновления прогресса. Обновление или закрытие вкладки не останавливает сервер. После перезапуска сервера незавершённый сбор отображается как приостановленный: нажмите «Продолжить сохранённый сбор». Уже сохранённые ответы повторно не запрашиваются. Если остановка произошла до записи ответа на диск, текущий запрос может быть выполнен повторно.

История показывает последние 30 запусков; более старые файлы остаются на диске. Автоматическое удаление не выполняется. Ошибки отдельных запросов не останавливают весь сбор — их можно повторить новым запуском. Одновременно допускается один сбор. Все пользователи общего пароля видят общую историю.

## Защита доступа

- Хеширование scrypt: N=32768, r=8, p=1, случайная соль 16 байт.
- Сеансы на сервере, случайные токены 32 байта, cookie HttpOnly и SameSite=Strict, срок 12 часов.
- Ограничение попыток входа: 10 за 15 минут на IP, не более двух одновременных проверок пароля.
- Без настроенного хеша доступ закрыт.
- API, история и Excel доступны только после входа. JSON-файлы не раздаются по HTTP.
- Запросы изменений с посторонних сайтов отклоняются; разрешённые адреса задаются в `APP_ORIGINS`.
- `.env`, ответы Wordstat и Excel исключены из Git.

По умолчанию сервер слушает только 127.0.0.1. Для внешнего доступа нужен отдельный HTTPS reverse proxy, `COOKIE_SECURE=true` и соответствующий адрес в `APP_ORIGINS`. Настройка публичного размещения в эту версию не входит. Не открывайте незашифрованный HTTP наружу.

## Проверка

```powershell
npm test --prefix server
npm run lint --prefix client
npm run build --prefix client
```

Тесты используют искусственные ответы и не обращаются к платному API. Проверяются вход, выход, срок сеанса, ограничение попыток, защита скачивания, пустые ответы и ошибки, сохранение общей и построчной частотности, восстановление после остановки, переключение листов и большой запуск из 120 исходных запросов с 240 240 строками семантики.
